  【一】手机端（窄屏 / 触屏，屏宽 ≤ 640px）
══════════════════════════════════════════════════════════════

  ── ◆ 功能 ────────────────────────────────────────────────────

  [2026-09-21] 悬浮播放窗初始大小
      改成约 2/3 屏宽，412px 手机视口实测宽 272px，跟截图里
      的大小一致。如果你自己手动拖过、缩放过，仍然会记住你
      调过的尺寸，不会被这次改动覆盖。

  [2026-09-21] 音乐搜索栏跟电脑端统一
      「搜索」按钮回到输入框右侧、同一行；「我的收藏 / 历史」
      一行放不下时自动排到下一行，不再各占一整行。

  [2026-09-21] 每日推荐改两列
      不再一列一张大卡片，一屏能看到更多歌。

  [2026-09-21] 「选择」键变正圆
      历史记录里的「选择」按钮空闲时是 48×48 正圆；进入选择
      模式后文字变长（变成 🗑 清理 / 取消选择），自动恢复胶囊
      形，免得被文字撑破。

  [2026-09-21] 游戏搜索框占位语精简
      删掉了「（比如：玛丽、坦克、僵尸）」，只留
      「输入游戏名字，一键搜索」。

  [2026-09-21] 游戏弹窗提示语精简
      删掉了「玩的时候会自动帮你缓冲后面 3 个游戏」这句话。
      预取后面 3 个游戏的功能本身还在，只是不再写出来。

  [2026-09-21] 删掉 TurboWarp 自带的方形放大按钮
      游戏弹窗里原来有两个全屏键：TurboWarp 播放器自带的方形
      ⛶ 和站内弹窗头部的圆形 □。现在只保留头部的圆形键，
      实现方式是去掉 iframe 的 allowfullscreen 属性（官方文档
      确认这是隐藏该按钮的正确做法），站内的圆形全屏不受影响。

  [2026-09-20] 手机端锁屏 / 切后台也能接着听
      接入系统媒体控件（Media Session）：锁屏界面显示歌名、
      歌手和 500×500 封面，耳机线控、媒体键可以上一首 / 下一首。

  ── ◆ Bug 修复 ────────────────────────────────────────────────

  [2026-09-21] 已修：搜索按钮在手机上被单独排到搜索框下面一行
      和电脑端不一致，看着很别扭。→ 改回跟输入框同一行右侧。

  [2026-09-21] 已修：每日推荐在手机上是一列大卡片
      一屏看不了几首歌。→ 改成两列。

  [2026-09-21] 已修：「选择」键在手机上被拉成椭圆形
      不符合圆形控制键的规范。→ 改成 48×48 正圆。

  [2026-09-21] 已修：手机上悬浮播放窗初始尺寸偏小
      跟预期对不上。→ 按截图改成 2/3 屏宽。

  [2026-09-21] 已修：游戏弹窗里多出一个 TurboWarp 方形全屏键
      它和站内的圆形全屏键功能重复，而且进的是 TurboWarp 自己
      的全屏，行为跟站内不一致。→ 删除方形键，只留圆形键。

══════════════════════════════════════════════════════════════
  【二】电脑端（桌面 / 宽屏）
══════════════════════════════════════════════════════════════

  ── ◆ 功能 ────────────────────────────────────────────────────

  [2026-09-20] 音乐跨页面不断播
      站内换页（作品集 ↔ 游戏库）只替换页面内容，播放器整个挂
      在常驻层里，<audio> 元素永不重建，音乐一秒都不会断。
      浏览器的前进 / 后退按钮同样支持。

  [2026-09-20] 浏览器最小化、切到别的标签页都继续播
      加上系统媒体控件（Media Session）：Windows 的音量键弹窗、
      锁屏界面都能控制播放。歌词滚动改成双驱动
      （timeupdate + 400ms 定时器），后台标签页 timeupdate 会变稀，
      这样也不会卡住，显示效果跟以前完全一样。

  [2026-09-20] 刷新网页接着播
      播放现场持久化（localStorage 键 hjy_player_state_v1），
      刷新后自动回到那首歌、那个进度。浏览器拦截自动播放时
      会提示点 ▶。

  [2026-09-20] 点歌手名弹出歌手页
      音乐卡片上的歌手名可以点（外观和普通文字一样，鼠标悬停
      才变色），弹出：歌手头像 + 单曲数 / 专辑数 + 简介 +
      热门 50 首 + 「▶ 全部播放」。全部播放会先过滤掉无版权
      歌曲，并提示实际可播的数量。资料用三个接口并行请求，
      鼠标悬停提前预取。

  [2026-09-20] 换页记住你看到哪儿
      主页上一次停留的那一屏（每日推荐 / 搜索结果 / 收藏 /
      榜单 / 页码 / 视图切换）和游戏清单都挂在 window 缓存上，
      回主页 186ms 出卡片，第二次来回只要 10ms。

  [2026-09-20] 历史记录多选删除
      可以勾选多条一起删，清空有确认弹窗。弹窗控制键是
      Windows 风格：− 最小化 / □ 全屏 / ✕ 关闭，三个键
      行为互相独立，最小化和关闭不会冲突。

  [2026-09-21] 放大后的歌曲封面变清晰
      详情页大封面改渐进加载：先显示 240 缩略图，500×500 的
      高清图加载完无缝替换；锁屏 / 系统媒体控件封面升到
      500×500；歌手头像按 300 取图。

  [2026-09-21] 修改日志页上线
      changelog.html，功能在上、Bug 在下，以后每次改动都会更新
      并把链接发给你。

  [更早] 音乐模块
      搜索 / 每日推荐 / 收藏 / 历史 / 分页 / 歌词滚动；
      悬浮播放窗可拖动、可缩放，位置和缩放都会记住；
      自动过滤掉无版权和 VIP 歌曲（这是明确要求）。

  [更早] 游戏库
      1866 个 Scratch 游戏，卡片点击弹窗直接玩，自动预取
      后面 3 个游戏。

  ── ◆ Bug 修复 ────────────────────────────────────────────────

  [2026-09-21] 已修：封面高清一直没生效
      bigArt() 原来只对「不带参数」的图片地址追加高清参数，而
      封面地址本来就带着 ?param=240y240，条件永远不成立。
      → 改成原地替换 param= 参数，而不是追加。

  [2026-09-20] 已修：site.js 启动函数死循环
      把子节点往数组里推的时候没有从 DOM 摘除，一直推到自己
      报 RangeError。→ 改成先快照子节点再搬移，并加异常兜底。

  [2026-09-20] 已修：主页 data-page="home" 属性丢失
      属性没了，页面脚本不执行，音乐卡片一个都不出来。原因是
      同一个文件的两处修改并行执行、互相覆盖。
      → 教训入档：同一文件的多处修改必须串行。

  [2026-09-20] 已修：歌手弹窗「全部播放」按钮文案不复位
      加载状态结束后按钮文字没还原。→ 结束时重置按钮文字。

  [2026-09-20] 已修：无刷新换页后模块级缓存全部重置
      换页会把页面脚本重跑一遍，模块级 var 缓存全没了，回主页
      要空白几十秒重新走一遍弱网请求。→ 需要跨页存活的缓存
      全部改挂 window。

  [2026-09-20] 已修：弱网下写进一份空的每日推荐缓存
      之后打开每日推荐一直是空的。→ 加 list.length 判断，
      空结果不落盘。

  [2026-09-20] 已修（部署脚本）：探测新文件的 sha 时 404 白等 60 秒
      被当成失败重试了 4 次。→ 404 直接视为「线上还没有这个
      文件」，继续往下走。

  【三】两端共通（后台 / 部署 / 数据）
══════════════════════════════════════════════════════════════

  ── ◆ 功能 ────────────────────────────────────────────────────

  [更早] 站点结构
      作品集 + 音乐板块 + 游戏库三个页面，用 GitHub Pages 托管。

  [2026-09-21] 游戏库扩容到 1866 个
      剩下的 149 个大文件（约 1.1GB）全部上架。因为单个仓库的
      Pages 有 1GB 上限，大文件分片放在三个仓库：
      主站 + hjy-games-2 + hjy-games-3，游戏清单里用 h 字段
      标记文件在哪个仓库。

  [2026-09-21] 两个超大文件的两条上行通道
      · 弹钢琴（28.10MB）：用 zip 无损重打包压到 23.67MB 走 API
        上传，内部 63 个资源逐字节完全一致，加载无差异。
      · 超级粉碎（31.69MB）：走 git push 二进制通道原样上传，
        线上 33,225,839 字节与原文件完全一致。

  [2026-09-21] 部署链路自动化
      Contents API 上传 → Pages 构建状态轮询 → 线上正 / 反向
      标记校验，整个过程幂等，可以随时重跑。

  [2026-09-21] 无头浏览器自动化测试
      CDP 驱动手机视口（412px）逐个验证 UI 改动，支持派发真实
      用户手势、截图、抓控制台错误。

  ── ◆ Bug 修复 ────────────────────────────────────────────────

  [2026-09-21] 已确认：中间网络设备有约 34MB 的请求体硬上限
      超过就被拦截，并伪装成 401 Bad credentials（同一个 token
      发小请求完全正常，所以一开始误判成 token 失效或限流）。
      实测 33.73MB 能过、35.33MB 必挂。
      → 所有上传改成单条串行、单文件超限就先重新打包压缩。

  [2026-09-21] 已修：同一台设备会伪造 201 和伪造 404
      上传 blob 返回 201 但内容并没落地，后面建提交就 404。
      → 上传后一律校验「返回 sha == git hash-object」，不一致
      就重传；404 一律当可重试处理。

  [2026-09-21] 已封档：Actions 服务端拼接大文件的方案不可行
      token 只有常规权限、缺 workflow scope，只要 tree 或 commit
      的路径里出现 .github/workflows/ 就直接返回 404（已隔离
      验证确认）。

  [2026-09-21] 已解决：git push 常年被墙
      github.com:443 建连 502。把 github.com 加进白名单之后变成
      间歇可用（约 1/6 成功率，失败很快、成功一次约 55 秒传完
      30MB）。→ 写循环重试脚本撞可用的窗口，推完再用 Contents
      API 校验 sha 和字节数完全相等。

  [2026-09-21] 封档：raw / codeload / uploads.github.com 全部 502
      release 资产上传、网页上传这些通道都不可用。
      另外 objects.githubusercontent.com 只读可用。

  [2026-09-21] 已修：提交信息里的中文被本机编码转坏
      UTF-8 字节被当成 GBK 解析，出「瓒呯骇绮夌」这类乱码，
      -m 和 -F 文件两种写法都坏。→ 提交信息一律写纯 ASCII。

  [2026-09-21] 已修：Pages 构建期间线上是「伪 404」
      大文件推完之后访问短暂 404，其实是 Pages 还在构建
      （1~3 分钟）。→ 校验之前先等构建状态变成 built 再验。

  [2026-09-21] 已修复流程：后台长任务被新消息打断
      新消息一到，还在跑的后台任务会被宿主同时收走。→ 改成
      每完成一个文件就落盘进度、整条链路幂等可续，被打断之后
      重跑同一条命令就能接着做。

  [更早] 已规避：本机 PowerShell 标准输出被吞
      重定向还会产出 UTF-16，经常要缓冲到进程结束才写出来。
      → 改用让 python 脚本自己写 UTF-8 报告文件，再读文件。
